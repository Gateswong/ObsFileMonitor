# 故障排查

先打开配置页面 <http://127.0.0.1:8765/> 看“运行状态”区域，大部分问题的原因会直接显示在那里。
需要更多信息时，用 `--debug` 启动查看控制台日志。

## 显示“OBS 未连接”

| 提示 | 原因与处理 |
| --- | --- |
| 无法连接：OBS 未运行，或未启用服务器 | 启动 OBS；在 **工具 → WebSocket 服务器设置** 中勾选“开启 WebSocket 服务器” |
| OBS 启用了身份验证，请填写密码 | 在配置页面填写密码（OBS 中点“显示连接信息”查看） |
| 身份验证失败：WebSocket 密码错误 | 重新复制密码；注意 OBS 中点击“生成密码”会更换密码 |
| 连接超时 | 检查主机地址、端口；远程连接时检查防火墙 |

程序会每 3 秒自动重试，不需要重启。

## 启动时报“无法启动配置页面（端口被占用？）”

`8765` 端口被其他程序占用，或者本程序已经在运行。先确认任务管理器中没有另一个 `python.exe` 在运行本工具；
否则修改 `config.json` 中的 `web.port` 后重启。

## 叠加窗口看不到

- 配置中 `overlay.enabled` 是否为 `true`；`show_when_idle` 为 `false` 时只在录制时出现；
- 窗口总是显示在**主显示器**上，检查 Windows 显示设置中哪个是主显示器；
- `text_opacity` 太低，或文字颜色与桌面背景接近（开启 `shadow` 或设置 `bg_opacity` 加背景）；
- 独占全屏的游戏会盖住所有窗口，改用“无边框窗口”模式运行游戏。

## 修改位置或边距后没有变化

0.2.1 之前的版本存在此问题（文字窗口停在原位置，只有背景窗口移动），请更新。
当前版本保存配置后 0.5 秒内生效，且无论文字多长，窗口都不会超出屏幕。

## 叠加窗口挡住了鼠标点击

在配置页面勾选 **鼠标穿透** 并保存。

## 叠加窗口被录进了视频

默认已开启 **不被录进视频**（`overlay.exclude_from_capture`），使用“显示器采集”时叠加窗口不会出现在录像中。如果仍然被录进去：

- 确认配置页面中“不被录进视频”已勾选；
- 该功能需要 Windows 10 2004（20H1）或更高版本；
- 改用“窗口采集”或“游戏采集”；
- 录制时临时关闭叠加窗口。

## 文件大小与资源管理器中不一致

- `directory` 模式每 15–30 秒扫描一次，叠加窗口中的大小最多滞后一个扫描间隔；资源管理器也可能缓存旧的文件大小，按 F5 刷新后再比对；
- `websocket` 模式显示的 `outputBytes` 可能是本次 OBS 会话所有录制的累计值，比当前文件大得多，请改用 `directory` 模式；
- 启用了“自动分割文件”时，`directory` 模式只显示当前分段文件的大小；
- 大小使用 1024 进制（1 GB = 1024³ 字节），与资源管理器一致。

## 目录扫描模式显示“尚未找到本次录制的文件”

- 确认 `recording.directory` 与 OBS **设置 → 输出 → 录像 → 录像路径** 一致，或留空让程序自动获取；
- 确认 `recording.extensions` 包含 OBS 使用的录像格式扩展名；
- 本工具只看目录第一层，不递归子目录（OBS 的文件名格式中带 `/` 会创建子目录）。

## 跳帧数后面带 `*`

启动本工具时录制已经在进行，无法知道录制开始时的计数，因此只统计了工具启动之后的跳帧。下一次录制会恢复正常。

## 跳帧数与 OBS 统计窗口不一致

OBS 统计窗口显示的是 **OBS 启动以来** 的累计值，本工具显示 **本次录制以来** 的值，两者不同是正常的。
详见 [ARCHITECTURE.md](ARCHITECTURE.md#两种跳帧的含义)。

## 双击 `start.bat` 后窗口一闪而过

在命令行中运行 `start.bat` 查看报错。常见原因：未安装 Python，或 Python 安装时未勾选 tcl/tk。
